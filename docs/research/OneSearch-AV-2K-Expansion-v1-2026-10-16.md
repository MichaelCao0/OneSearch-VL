# OneSearch-AV：2K 训练数据扩产方案

本轮目标是形成 **2,000 个不同问题的搜索轨迹 SFT 训练集**。每题包含真实音视频输入、工具调用与 observation、最终答案，并配套同题 answer-only 对照。配对导出不增加问题数量。2K 是训练扩量实验的里程碑；完整论文的数据目标仍为 20K train、500 train-validation、200 benchmark dev 和 1K test。

主开发与运行位置：`coder ssh 3:/home/jovyan/OneSearch-VL`。数据生产用 Pixi 环境直接在 CPU 后台运行。Student 继续采用 Qwen2.5-Omni-7B，复用 OneSearch agent loop 与原 `SFT/src/train.py`。

## 3. 已启动的生产流程

Run：`/home/jovyan/OneSearch-VL/research/runs/av-data-production-20261016-v10/`。

1. **回收已经成功、从未进入轨迹阶段的出题结果。**上一轮留下 11 段录制、20 个接受的问题；复用成功回执，直接准备搜索任务，新增出题 API 调用为零。先跑 1 题完整链路，再进入剩余问题。
2. **处理既有未调用素材。**全局排除 2,080 个已付费出题来源及其候选家族后，还找到 9 段未调用录制；实际媒体准备成功数另行记录。
3. **后台补采新素材。**搜索词由 69 组扩为 835 组，覆盖乐器与演出、不同赛事、活动与仪式、机械与环境等。每批轮换起点，结合全局已见 page ID 排除旧素材。
4. **预留 benchmark 来源，再准备训练输入。**真实裁剪及转码、保留基本时间信息；每录制最多生成两题，控制同源重复。
5. **Teacher 生成搜索轨迹。**Teacher 原生接收音视频，执行原 OneSearch 工具循环，在当前冻结语料中搜索、查阅并回答。
6. **轨迹语义保留、配对导出和 CPU 检查。**合格轨迹与同题 answer-only 成对导出，经原 trainer 检查真实音视频输入和 supervised labels 后，才纳入 `verified_pool()`。
7. **最终筛选和数据冻结。**排除已知 reject/revise/control/unknown，保存 2K 的精确 membership、行哈希、媒体绑定、来源家族和训练输入统计。内容抽检通过与未抽检 silver 分别标记。

用户已认可的扩产重点是赛事、活动与音乐。采集调度权重为 music 30%、sports 30%、live 20%、other 20%；这是 query 调度权重，实际下载比例和内容类别须从结果分别统计。

## 4. 本轮吞吐改动与预算

**采集和模型生产重叠运行。**独立 CPU 采集进程最多缓存两个尚未消费的 cohort，避免后续模型阶段持续等待下一批素材。公开素材仍串行、按 API pace 采集并遵守 cooldown。

**每 cohort 统一构建一次检索语料。**原流程每 48 段出题就扫描全量累计音视频并重建语料；新流程完成该 cohort 的出题后统一 materialize，再将问题按至多 48 题切分并行生成轨迹。该改动已在新 run 脚本中实现，端到端提速需以完成批次的实测比较。

**并发按阶段设置。**出题 4 workers，轨迹/语义保留 8 workers；当前服务连续两轮出现 502/503 burst，先用较低出题并发验证稳定性。单条轨迹内部的多轮请求有因果依赖，不能直接并发。

历史请求内耗时有约 99.7%–99.9% 在 API 等待及响应解析；这个比例不包含采集、家族 inventory、materialize 和 CPU audit，不能当成整个生产流程的 API 占比。最近 36 个候选的实测为 rollout 258s、review 61s、CPU audit 272s，CPU audit 同样影响吞吐。

| 本轮约束 | 上限/安排 |
|---|---|
| CPU 合格问题目标 | 2,200；最终选择 2,000 |
| 新增出题请求 | 2,500 |
| 新增轨迹候选槽位 | 5,000；单轨迹至多 8 次模型调用 |
| 素材批数 | 16，按 12 批作为中心估计 |
| 每批采集 | 目标 250；最多 700 次下载、15 GB、单素材 150 MB |
| 总采集字节预算 | 最多 240 GB，包含失败下载；当前约 660 GiB 空闲 |
| 时间预算 | 24 小时，为停止边界，不是完成时间承诺 |
| GPU 提交 | 本轮数据生产为 0 |

历史完整生产约为每保留 1 题消耗 7 次模型请求。新增约 1K 题可先按约 7K 请求估算，再以 token usage 和实际失败率更新。网关价格未核实，不给出虚构人民币成本。

失败或结果未知的付费调用不重放；同一分钟三次 provider 错误暂停该 run，保留在途结果。新版本只处理未调用素材与已成功但尚未使用的结果。公开 Commons API 的 read-only backoff 与付费模型调用是两套策略。
