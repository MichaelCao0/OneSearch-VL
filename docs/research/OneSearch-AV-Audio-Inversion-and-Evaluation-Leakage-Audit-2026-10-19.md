# OneSearch-AV：倒挂解释、声音收益与评测泄露审计

日期：北京时间 2026-10-19。此次在 Coder 4 对实际冻结的 500／2K SFT 导出、行级 lineage、评测清单与检索 scope 重新审计；没有新增模型/API请求、GPU任务或训练数据修改。

## 当前判断

之前确实出现过静音优于原声。历史输入问题、不同训练版本、评分上下文和有效题集合需要分别处理。当前 2K 原声相对静音的净优势仅为联合评分中的 2 道题；相同答案在两种评分上下文之间发生了 3 道原声成功标签变化，因此目前没有稳定的音频增益结论。

当前 500／2K 实际训练文件没有发现本次评测题的精确样本、已登记家族、媒体哈希、目标／支持 URL 或完整页标题重叠。这是可复核的直接隔离结果。现有 56 题属于反复使用的开发／诊断集合，尚不具备独立、封存、人工核验的论文 test 条件；录制隔离也没有做到实体隔离。

## 之前的倒挂来自哪些结果

| 版本 | 原声 | 静音 | 解读 |
|---|---:|---:|---|
| 历史 500 LoRA，development 16 | 9/16 | 13/16 | 历史训练成员与当前 Full Thinker 不同；旧推理存在音频 token 路由问题，音频因果比较失效 |
| Full Thinker 500，修复前 development 16 | 11/16 | 12/16 | 同样属于旧输入路径；该次共同 heldout 38 原声／静音均为 18/38 |
| 修复后 2K，中期双候选评分，全部 56 | 35/56 | 36/56 | 真实修复后 rollout，初步评分仍出现倒挂 |
| 修复后 2K，中期评分，只取最终共同 52 题 | 33/52 | 34/52 | 与下一行的题目和答案完全相同 |
| 修复后 2K，最终十候选联合评分，同 52 题 | 36/52 | 34/52 | 3 个原声答案标签改变，静音成功标签未变 |

前两行的原生音频不能只凭 input_features 存在而判定有效：旧 OmniRunner 混用了 flat video 参数与 videos_kwargs，pinned ProcessorMixin 忽略了部分参数，真实案例出现“音频特征存在、audio token 为 0”。已修复并在实际 GPU 每轮验证 token/feature 绑定。异 FPS 多轮路径另有显式 token 展开，因此也不能概括所有历史轮次都没有声音。

最后两行表明：从倒挂到正向，不能全部解释为修复或训练效果。十候选联合评分在中期评分完成前已经写入冻结计划，并非看到结果后挑选较高分数；但自动 judge 对别名、错误附加断言和中英文冲突的处理存在上下文敏感性。主表保留预先指定的联合评分，同时完整保存评分分歧。

## 500→2K 增益减少是否由语音导致

同 52 题的 trajectory SFT 结果为：

| 规模 | 原声 | 静音 | 原声减静音 |
|---|---:|---:|---:|
| 500 | 33/52 | 28/52 | +5/52，即 +9.6 pp |
| 2K | 36/52 | 34/52 | +2/52，即 +3.8 pp |
| 2K 减 500 | +3/52，即 +5.8 pp | +6/52，即 +11.5 pp | -3/52，即 -5.8 pp |

原声的绝对成绩上升；静音成绩上升得更多，使“额外音频优势”减少。新增计算的配对交互项为：

`(2K_AV - 500_AV) - (2K_muted - 500_muted) = -5.8 pp`。

按 38 个自动录制家族进行 10,000 次配对 bootstrap，95% 区间为 **[-19.2, +7.8] pp**。该区间不能确认真实负交互，更不能归因于语音。现有原声条件同时包含语音、音乐、动物叫声和环境声；56 题的 audio_required 字段全部仍为 pending_content_review，没有可靠的声音必要性分层。

现有观察更支持两条待检验解释：当前数据主要教会查询、阅读和回答等通用搜索动作，静音也能受益；音频有时改变查询并帮助定位，有时引入错误实体假设或额外搜索。此前 2K 结构审查中，1557/2000 仅一次 text_search，1917/2000 的 support_quotes 只引用一份文档。它们并未系统要求利用声音完成多跳依赖。

这些是机制线索，不是语音导致性能下降的实验证明。同 2 epochs 的规模比较还包含 250→1000 更新和约 4 倍 token 量的变化。

## 这两组评测题是如何构造的

| 集合 | 题数 | 自动录制家族 | 实际输入文件哈希数 | 检索环境 |
|---|---:|---:|---:|---|
| heldout_silver | 40 | 32 | 32 | 原批次冻结语料；每个环境约 97–591 个公开 URL |
| development publisher candidates | 16 | 8 | 16 | 一个早期固定开发库，16 个文档、10 个公开 URL |
| 合计 | 56 | 40 | 48 | 最终有效评分 52 题，涉及 38 家族 |

40 题来自早期生产的 silver 候选，而非外部独立 benchmark。构题管线让 Gemini 读取真实 AV 与对应 publisher_text，生成问题、私有声画线索、可接受答案字段；答案的 canonical value 被要求原样存在于发布说明。后续使用真实工具回放和自动保留检查。`learning_pilot.group_holdout` 根据 family_id 与相同媒体哈希的传递连接分组，再做确定性留出，避免同一已登记家族分到两侧。该 heldout 此后持续沿用。

16 题是早期围绕 8 个录制家族编排的开发题，每个家族两题。它们的输入文件可以是不同切片／处理版本，所以有 16 个文件哈希，不代表 16 个独立录制。参考字段取自发布说明与冻结网页；这些题用于 prompt、工具与输入路径的开发验证。

当前 500 与 2K 都重新从 pinned base 开始训练，没有续用早期 172 LoRA。训练冻结时对保留评测的来源 URL、哈希和家族做过滤，并扫描实际 teacher trace 中的保留 URL；此次又直接扫描了训练所用 ShareGPT trajectory/answer-only 文件，而不仅仅检查配置声明。

部分旧 task/scope 的 split 仍显示 train，是它们从早期生产池中被留出后保留的历史字段。是否真正入训应看冻结 SFT 文件、成员清单及行级哈希。本次这三者已重新绑定核验。

## 当前训练数据的直接重叠检查

对全部 56 题检查，包含评分失败的 4 题：

| 检查项 | 当前 500 | 当前 2K |
|---|---:|---:|
| 相同 task ID | 0 | 0 |
| 规范化后相同题面 | 0 | 0 |
| 相同已登记 family_id | 0 | 0 |
| 相同已登记媒体 SHA-256 | 0 | 0 |
| 目标／支持 URL 出现在 trajectory 或 answer-only 训练文本 | 0 | 0 |
| 目标／支持页面的完整标题出现在训练文本 | 0 | 0 |

所有导出行均与训练 lineage 的 row_sha256／answer_row_sha256 匹配，成员文件 SHA-256 与实际 Full Thinker 训练计划匹配；500 是 2K 的严格子集。

早期 172 训练版本曾有 18/40 heldout 的参考页面出现在训练 observation；旧记录保留，不能将当时结果纳入当前干净规模对照。当前审计没有复现这项直接 URL 曝光。

评测执行中，actor 接收匿名 AV、问题、通用工具 prompt 和实际检索结果；参考字段和 support_quotes 用于预测后的判分与诊断计数。评测检索库包含能够回答问题的公开页面，是搜索任务的环境设定；与“训练时已经见过该评测页面”是不同的暴露路径。

## 尚未隔离的重叠与评估偏差

- **实体和答案可共享。** 例如训练集已有白鲸 Delphinapterus leucas 的其他录制，也有其他贝多芬作品；heldout 仍可能考同一物种或同一作曲家。当前是录制留出，并非实体／事实留出。
- **同系列或转载的语义近重复没有完成人审。** 精确 SHA、页标题和自动 family_id 检查无法排除不同编码、不同裁剪、镜像转载或同一事件的另一个拍摄版本。此次没有做全量视觉／音频指纹近重复审计。
- **集合已经用于迭代。** dev 明确用于开发；40 题也被反复查看和评测。即使样本不入训，也不再是一次性封存 test。
- **构题和评分的同源偏差。** 题目多为发布者属性 lookup，参考来自相同元数据路径，Gemini 同系列模型参与生成和自动判断；独立人工 gold 尚未完成。
- **环境捷径。** 尤其 dev 仅 10 个 URL，题面、有限候选和元数据就可能支持猜测或弱检索，不一定需要充分使用 AV。题目只有声音描述，也不证明声音不可替代。
- **预训练污染未知。** 这些训练文件的审计不能证明公开模型的预训练语料从未见过相关公开视频或页面。

对答案字符串另做了候选扫描：500 对应 8 道、2K 对应 10 道 heldout 的可接受答案字段可在某个训练最终回复中找到。但其中包含通用年份、作曲家或物种；字符串相同本身不等于同一问题／同一事实泄露。ASCII 边界过滤已排除把 Trang 错匹配到 Stranger 的情况；原始 v1 与修正 v2 回执均保留。

## 后续 benchmark 应如何收敛

这 56 题继续作为开发诊断套件。正式 test 在原始录制／转载家族层面先分组封存，并在训练构题和 rollout 前隔离其目标／支持页。再用声画指纹和人工抽查处理近重复，分别报告同实体新录制和未见实体子集。

新题保留可核实的 AV 锚点与事实依赖；标注声音是必要、增益性还是冗余，覆盖语音、音乐、非语音声音。增加 question-only、静音、仅音频、AV，以及无关 AV 干预，检查答案是否真的随媒体证据变化。检索采用更大的统一语料或固定预算在线 Search/Fetch，避免小候选库捷径。

开发集用于调 prompt 和选择方案；正式 test 一次冻结、独立审核、固定判分规则。继续比较 500／2K 时补充等 token／更新预算控制，再判断数据规模与音频任务构成各自的收益。
