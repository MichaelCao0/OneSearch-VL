# OneSearch-AV：在线组合构题实现与媒体传输诊断

日期：2026-10-19；主代码位于 coder ssh 4 的 /home/jovyan/OneSearch-VL。

## 当前实现

`research/av_train/online_data_engine.py` 实现音视频锚点发现、真实 DeepSeek Search/Fetch 事实扩展、显式依赖构题、独立 QA 验证与 question-only probe、teacher 在原 OneSearch agent loop 中自主搜索，以及答案/过程审核和原 SFT 格式导出。`compositional_graph.py` 验证事实链连续性、实际网页引文、实体指代隐藏、算术/比较/条件计数答案；派生答案不再要求原样出现于发布者说明。

`online_data_review.py` 提供完整实际输入的原声、静音、只听声音审核页面，并合并同题 trajectory/answer-only 导出。数据生产直接使用 CPU；GPU 训练和评测通过项目 kjob launcher。

## 实际执行结果

目标是先保留 64 道不同新问题，质量检查通过后扩到 500 道做训练对照。首批从已有 train 录制中重构问题，排除固定评测录制家族；不是新增的独立录制数据集。当前合格的新组合训练数据为 0 条，尚未进入 500 条扩产或新训练。

真实 Search/Fetch 已执行，返回的正文和请求收据保存在版本化运行目录。初版要求每条事实来自独立 Fetch 正文，在部分 Fetch 返回 404/504 时丢弃了 Search 已返回的正文；后续需要统一这两种真实正文来源，并保留证据类型。

首次兼容调用误用了原生接口前缀，得到 HTTP 404；随后修正。`gemini-3.1-pro` 在原生和正确的兼容接口均返回 HTTP 503，目录中的型号存在不代表生成可用。

更关键的内容检查发现：本次 `gemini-3.8-flash` 的 OpenAI 兼容 `video_url` 路径对实际机械乐器视频描述为沙拉制作，对马拉松历史影像描述为芝士蛋糕制作，对教堂钟楼视频描述为林间步道。实际输入帧与模型描述明显不符。因此 `av-online-compositional64-20261019-v4` 已隔离，全部收据保留，该运行不能提供训练样本。HTTP 成功与媒体字节收据不能代替实际媒体理解验证。

该结论限定于本次具体 provider/model/endpoint/transport 组合；此前原生 generateContent 数据需要依据各自输入和审核记录判断。

## 下一步执行

1. 使用原生 Gemini generateContent 路径，对真实音视频进行内容对照：至少核对画面主体、可辨认声音及跨视频差异，再启动生产。已确认内容错配的兼容传输组合在新入口中拒绝执行。
2. 优先使用内容审核通过的 train 来源；Search 返回正文与 Fetch 正文都按真实抓取来源保留，摘要与原文分别标注。
3. 按同一五阶段流程完成 64 条，检查组合题比例、必需事实链、实体绑定、实际在线解题成功和音频贡献。
4. 将合格的 64 条包含在后续 500 条中，沿用同一基座和匹配训练 recipe，对比旧 500、在线组合 500 trajectory 与同题 answer-only；训练后立即在线评测原声/静音。

本次发布为代码和研究记录的可审查版本，未声称在线数据生产已经完成或取得新训练收益。
