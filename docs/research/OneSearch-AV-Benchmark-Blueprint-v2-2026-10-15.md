# AVSearch-Bench v2：独立音视频搜索问答 Benchmark 建设方案

日期：2026-10-15。目标 1,000 正式 test + 200 dev，共 1,200；人工 gold 当前 0。现有 40 heldout silver + 16 development candidates 用于工程与探索，不自动并入正式 benchmark。

## 1. 要测的能力

给定匿名真实 AV 片段与自然问题，agent 从声画线索构造搜索，找到相关来源，读取外部事实并直接回答。题目可由一个来源回答，也允许必要的多来源；不强制研究报告。

主难点是“从不知道名称的 AV 线索找知识”，不是单纯描述片段、回答网页已经给出的信息或读文件名。benchmark 必须用自然音视频、可核实事实和有意义的干扰来源说明这个能力。

## 2. 规模与阶段

| 阶段 | 目标 | 用途 |
|---|---:|---|
| 来源预留 | 先预留约 2,000 个新候选录制家族 | 在后续 train 生产前建立隔离 |
| 人工构建 pilot | 100 道合格题目标 | 测题目质量、标注耗时、自然模态配比、评分器；归入未来 dev |
| benchmark dev | 200 题 | prompt/预算/judge 校准，家族与 test 隔离 |
| benchmark test | 1,000 题 | 最终主表，冻结后不按模型成败改题 |
| 全集来源覆盖 | 至少 1,000 个独立录制家族目标 | 每家族最多两题；转码/转载/多个片段不增加独立性 |
| 搜索环境 | 暂按至少 10K 媒体来源及相应网页 | 目标来源和同类干扰在同一索引，100 题 pilot 后锁定难度 |

100 题 pilot 在统计上属于 dev，不是新增第 1,301 题。若候选保留率低，扩候选来源，不降低 gold 核验标准凑数。训练来源不挪作正式 test。

## 3. 内容覆盖与模态分层

领域候选为音乐/表演、机械/技术、动物、鸟类/自然声、活动/环境。暂按每类 240 题（40 dev + 200 test）规划，共 1,200。领域名称与配额在 pilot 后冻结；自然样本可得性不足时报告实际分布。

模态目标为联合 AV 40%、声音主要线索 20%、视觉为主 30%、ASR/文本控制 10%。test 对应 400/200/300/100，dev 对应 80/40/60/20。模态角色与领域交叉标注，不要求所有组合人工补齐。

问题覆盖作品/曲目/物种/机型/事件身份，以及与正确实体相关的地点、年份、人物、功能等外部事实。区分发布日期、录制日期和活动日期。避免 uploader/网站 trivia 成为主要任务，也不强行把无法公开核实的身份设为唯一答案。

音频必要性不由出题模型或待测模型胜负决定。两名 reviewer 分别检查 full AV、静音、audio-only、video + ASR 下有哪些线索可用，记录必要/帮助/冗余及理由；对“单模态也可能靠先验猜中”和“原始片段含可直接读出的文字”单列。

## 4. 题目构建与人工审核

1. 先从未用于 train/teacher rollout 的录制家族选自然素材，保存完整来源和足够上下文；构建匿名约 10–60 秒候选，常见 15–40 秒，不默认 2 秒。实际时长和事件覆盖由人工审核。
2. 构造不泄露身份的自然问题和私有参考；题目不得复述能够直接定位的账号、标题、文件名、URL 或完整 ASR 中的答案。
3. Reviewer A 盲看片段与问题，先作答/检索，再核对来源、事实、区间和可接受答案。
4. Reviewer B 独立完成同样过程，不看 A 的结论；gold 依赖两人实际核实，不以 AI 建议代替。
5. 分歧由第三人裁决；记录保留、改题、删除及原因。媒体不充分、答案不唯一且无法定义可接受集合、来源事实矛盾的题目不能强收。
6. 双审音频/视觉/搜索角色；保存支持事实的网页快照和支持识别的媒体区间。声音能支持实体识别，不自动支持网页上的年份/地点。
7. 在正式评分前冻结答案、别名、事实含义、替代来源规则和 split；新发现有效答案走统一裁决并发布新版本，对全部模型重算。

报告逐项一致率与适合类别标签的 Cohen's kappa；答案正确性用字段一致率与裁决率。仅做多人签名或在同一 AI 答案上点“同意”不能视作独立盲审。

## 5. Split 与输入隔离

train、train-validation、benchmark dev/test 按原始录制家族隔离，同录制的媒体、裁剪、网页、转载与近重复必须在同侧；不按随机题目划分。自动指纹/URL 给候选关系，人工补查 benchmark 的近重复和同事件关联。

Actor 只收问题、匿名 AV、合法工具说明。私有 reference、家族映射、来源路径、答案及构造 cue 不进入 prompt。匿名查询 clip 不加入检索 corpus；目标原始来源必须由实际搜索发现。

训练检索返回也要过滤 benchmark 参考网页/家族，不能只隔离输入媒体。背景 distractor 可以共享，但不能通过 train observations 暴露正式测试目标。模型预训练污染未知，记录采集时间与公开来源，不声称彻底排除。

## 6. 搜索环境与预算

主表使用冻结 corpus：保留页面与媒体版本、采集截止时间、索引构造、检索模型/参数和可获取性，所有系统共用。网页与 AV 返回为实际来源，不包含 gold 排序或答案标签。索引中加入相似机器/动物/乐器/地点/声景，测具体来源区分。

现有检索协议映射为 text_search、visit_webpage、inspect_av。现有 pilot 使用 8 turn、512 tokens/turn；正式预算在 dev 测试后冻结候选 8/16 turn、1,024/2,048 tokens/turn，并记录执行工具数、媒体秒数、生成 tokens、wall time。闭源服务成本另列；同工具预算不等于相同算力，必须报告。

固定快照主结果与开放 web 转移分开。当前没有 Serper，不把开放 web 视为已有执行能力；不因联网接口未配就阻塞主 benchmark。候选 corpus 规模 1K/5K/10K 可在固定题目上做干扰密度分析，不按 test 结果选择主预算。

## 7. Baseline panel：follow OneSearch-VL 的训练比较

| 编号 | 系统 | 比较目的 |
|---|---|---|
| B0 | Qwen2.5-Omni-7B direct QA，无搜索 | 外部知识是否必要、模型先验能解决多少 |
| B1 | 同基座 prompted search | 充分调好的工具 prompt + 独立 train few-shot，衡量不训练的强起点 |
| B2 | 同基座 answer-only SFT | 同题直接答案蒸馏 |
| B3 | 同基座 trajectory SFT，OneSearch-AV | 主方法：实际工具行为与 final 的监督 |
| B4 | 原版 OneSearch-VL-8B 视觉搜索 | 原方法在同任务上的参照；不假装有音频输入 |
| B5 | video + ASR 模块化搜索 | 常见声转文方案与 native AV 的差别 |
| B6 | 强闭源 native AV teacher，工具和索引相同 | 能力参照及成本，不作为同模型训练归因 |

B1 必须在 dev 调好并冻结；当前 base 0/39 不是正式强 baseline。B2/B3 共用题目/基座/工具和预算，并报告相同 epochs 与近似训练计算量两种比较。另可做相同完整 observation 上下文、仅 mask action loss 的辅助对照；它与当前 answer_only_row() 不同，不能混称。

优先把这七种系统跑扎实。第二个 Omni 基座是泛化补充，不是开始主实验的先决条件。

## 8. 指标与评分

主指标 Task Success：在预算内形成合法 final，所有请求事实正确，无实质矛盾。程序根据协议状态与语义 verdict 联合计算，不能只让 judge 看一个答案字符串而忽略未完成 episode。逐字段分数辅助分析部分正确。

Supported Success 进一步要求答案中的实质断言受实际已见来源支持；候选参考源不是唯一合法来源。Source Retrieval 报实际搜索 top-k 命中/最终读取与替代有效来源；source hit 不等于答对。

成本报告工具次数、重复相同调用、媒体秒数、输入/输出 tokens、时延、GPU 时间或 API 实际费用。强模型与小模型的费用轴分开，工具数更多不奖励。

自动 judge 使用匿名、顺序随机的回答和明确 rubric，先在至少 200 个由人标注的系统回答上校准（可来自固定 dev 子集），报告一致率、误判和分组差异；选定后冻结。dev 的答案正确性、benchmark gold 与模型回答判分是三种不同人工工作。

正式模型执行失败计入任务分母；基础设施失败可以统一重跑，但需保留失败记录和同条件策略。judge 失败报告 unknown 和全体任务完成上下界；不能将 unknown 当正确或直接抹掉。置信区间按录制家族聚类 bootstrap，方法比较用配对差值；训练随机性另用多 seed 描述。

## 9. Analysis 与论文图表

- 按声音关键、联合、视觉、ASR 控制、领域和事实类型分组的成功率。
- AV vs 静音、audio-only、ASR 的同题差值；分别看声音怎样改变 query/来源选择。
- source oracle、正确网页 oracle 在 dev 小子集上定位瓶颈，明确额外信息，不混主表。
- 训练规模、监督类型、模态分层、干扰项难度的影响。
- retrieval hit 但 final 错误、重复搜索、时间/地点混淆和附加幻觉。
- 固定题目的成功率—工具/时间/费用曲线，及 corpus 大小变化。
- 自然案例与干预换音分开，干预的答案定义需要重新核实。

当前 clean500 在 heldout AV 23/39、静音 21/39，dev AV 8/15、静音 13/15。这个结果直接说明需要新的独立、模态角色清楚的 benchmark；不能用“更多工具调用”解释为声音能力已建立。

## 10. 发布包与工作量

发布包目标包含题目、匿名媒体或获取脚本、split、gold/别名、参考来源与证据区间、模态标签、搜索快照/重建说明、评分脚本、baseline configs/results、数据卡。受限媒体按实际许可提供来源和重建说明，不承诺全部 bytes 可公开。

人力规划：1,200 × 2 reviewer × 12–20 分钟 = 480–800 人时；20% 分歧每题裁决 10 分钟约 40 人时。100 题 pilot 先校准。最终 100 test 人类盲搜 baseline 两人、10 分钟/题约 33 人时。正式 test 冻结、人工资源和可重建搜索环境与训练扩量并行推进。
